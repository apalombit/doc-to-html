## Part A — our side first

For each group, in the order round 10 settles:

1. **Reproduce it on a dev page.** Pages found by the dev run's checks
   (question 2) or, without it, by the manifest's features, parsed with
   `tools/d2.py --parse`. A fault seen only on a panel page is not
   fixed until a dev page shows it.
2. **Fix it on our side**: the adapter, `locate`, the looks, the
   renderer. Never the parser's weights, prompts or thresholds
   (`parser/glmocr.yaml` unchanged).
3. **Pin it** by a test on dev pages or regions built by hand
   (`tests/test_adapter.py`'s way). No panel page in a test.
4. **Judge it by eye** on every dev page it moves: `tools/d2.py --sheets`
   draws each moved page beside its source and its previous render;
   better, same or worse, with the element named. Net gain ships; every
   worse page is named and goes next in line.
5. **Prove today's pipeline unmoved**: `tools/replay_run.py
   tests/frozen/s14-result` 21 of 21 byte-identical, 0 asked
   differently, at each group's close; the suite and `mypy src/`.

A rule needs several pages of its kind behind it; a rule that fires on
one page is a page fix, kept only if it costs nothing (`level-up.md`
§7).
